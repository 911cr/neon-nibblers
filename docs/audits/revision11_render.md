# Revision 11 animation and presentation review

2026-11-08. Two passes over actual App render calls, animation caches, clipped pixel regions, paused state, native-size surfaces and scripted effect sequences. No physical controllers used. Original artwork remains independently authored; these checks do not establish pixel identity with DX.

## Pass 1: concrete animation defects

1. **Identical collectible identity changed with sort order.** The old cache used `(power name, sorted index)`. When two items of the same kind reordered by x coordinate, or the earlier item disappeared, a surviving item could inherit the wrong visual position. Root replaced sorted index matching with nearest periodic position assignment. Tested two legal same-kind routes reversing their sort order, later collection of one item, and wrapping through the side tunnel. The surviving item's track is retained; obsolete tracks are removed.
2. **Lightning-stunned ghosts did not receive their visual stun state.** Main ghost draw used only the global stun flag and ignored per-ghost zap timers; the tunnel duplicate always passed false. Root now supplies the same combined global/per-ghost state to both images. Intercepted actual `foe` calls to verify a locally stunned ghost at the seam produces two stunned images exactly one map period apart.
3. **Paused world animation kept moving.** Match logic stopped, but mouths/effect phase, interpolation and popup lifetimes continued in `draw`. Root freezes world draw time for pause, guide and results. Tests snapshot animation time, player/ghost/item caches, popup positions/lifetimes and full Match digest across repeated half-second draws in all three states; all remain unchanged.
4. **Short respawns could interpolate instead of resetting.** The previous distance threshold alone did not distinguish teleport/respawn from travel. Root now clears affected player position cache on the `player_hurt` event and clears world caches on `stage_start`. Tested death at the bay entrance and stage transition near the bay: the resulting first frame uses the actual new position.

## Pass 2: motion, scope and clipping

Root added original time-based flame motion and electrical-arc jitter. The final artwork revision uses a continuous warm-colored plume with a pale core instead of a row of discs. Tests capture actual isolated plume pixel bytes and zap polyline vertices: both change across active frames, remain identical during pause, and are submitted with the maze clip active. A separate pixel comparison activates smoke, fire and electricity near top and bottom boundaries; every pixel in the station/HUD strips outside the maze remains unchanged.

Final plume integration was checked on all four layouts: a blocked forward path submits no plume; left and right tunnel wraps submit exactly two forward-pointing runs, each no longer than the five-cell reach. The middle playfield pixel strip remains unchanged, ruling out an accidental flame drawn across the whole board during wrap. The world-effect contact sheet was regenerated with this final continuous plume.

The 1/2/8-player scene was rendered on all four maps at both 1280×720 and 1920×1080, including the longest no-controller footer. All 24 combinations preserve Match state, retain the requested display size, and keep the footer inside the logical image. This is rendered surface validation, not an assertion of physical monitor configuration or readability from cabinet viewing distances.

## Results and limits

`test_revision11_render.py`: **10 tests PASS**. A palette test exercises F12 changes on every layout: all four palettes produce distinct background pixels containing the selected accent, cache entries include map ID/revision/palette, and the complete Match state/event digest remains unchanged through every switch. This validates independent visual palette selection without pretending that the authored layouts themselves have been reconstructed from DX. The final added test covers continuous plume wall-stop and both tunnel seams as described above.

This is a finite set of sequences and edge cases, not exhaustive proof for every possible frame, player arrangement or hardware scale. Nearest-position item tracking is presentation-only; it is not a new physics identity system. Visual timings and silhouettes remain original tuning with DX uncertainty recorded separately. Commercial art/animation identity, cabinet monitor behavior and physical controls are not certified by this review.
